# Приёмочный чек-лист: отчёты клиник + учёт ОХ

Документ для сдачи работы Аркадию. Прогоняется **после** деплоя
(см. `DEPLOY_CLINIC.md`) на проде.

## Что нужно подготовить до прогона

- Один тестовый аккаунт **ZMed-сотрудника** (супер): `username/password`, у него
  modules включают `clinic_reports`, `clinic_stock`.
- Один тестовый аккаунт **клиника-A** (НЕ супер, `Organization kind=clinic`),
  modules = `clinic_reports`, `clinic_stock`.
- Один тестовый аккаунт **клиника-B** (другая организация) — для проверки RLS.
- 1-2 JPG/PDF-файла размером до 20 МБ для прикрепления.
- Телефон с камерой (для скан-теста) и USB/BT-сканер штрихкодов (если есть).

Каждый сценарий отмечается: ✅ пройдено / ❌ не пройдено / ⚠️ замечание.
Дата и подпись в конце.

## A. Доступ и разграничение (RLS)

**A1. Клиника-A не видит отчёты клиники-B**
1. Залогинься как клиника-A.
2. Создай один отчёт (патиент_код, врач, тип — любые).
3. Залогинься как клиника-B → страница «📋 Отчёты клиник».

Ожидание: клиника-B НЕ видит отчёт клиники-A. Список пуст (или содержит
только отчёты клиники-B, если такие были).

Результат: ⬜

**A2. ZMed видит все отчёты всех клиник**
1. Залогинься как ZMed-сотрудник.
2. Открой «📋 Отчёты клиник».
3. В фильтре «Клиника» выбери «Все».

Ожидание: виден отчёт клиники-A и любые отчёты клиники-B.

Результат: ⬜

**A3. Клиника не может править чужой подписанный отчёт**
1. Залогинься как клиника-A, автор отчёта из A1 → открой отчёт → «Отправить»
   (статус станет `submitted`).
2. Залогинься как клиника-A другим пользователем (если второй есть) → открой
   этот отчёт → попробуй изменить поле «Диагноз».

Ожидание: кнопка «Сохранить» недоступна или выдаёт «Отправленный отчёт нельзя
редактировать» (HTTP 409).

Результат: ⬜

**A4. ZMed может править подписанный отчёт — с пометкой в аудите**
1. Залогинься как ZMed → открой `submitted`-отчёт из A3 → измени поле.
2. Открой вкладку «Аудит» этого отчёта.

Ожидание: в аудите появилась запись `edit_after_submit`, автор — ZMed-юзер,
время — свежее. В снимке (snapshot_json) — старые и новые значения видны.

Результат: ⬜

## B. Отчёты об операциях — создание и жизненный цикл

**B1. Создать отчёт через визард**
1. Клиника-A → «📋 Отчёты клиник» → «+ Новый отчёт».
2. Пройди все шаги визарда: patient_code (обезличенный, напр. `OP-2026-001`),
   дата операции, отделение, ФИО врача, тип операции, диагноз, список
   использованных имплантов (артикул + кол-во + lot), осложнения, заметки.
3. Нажми «Сохранить черновик».

Ожидание: отчёт появился в списке со статусом `draft`, виден только автору.

Результат: ⬜

**B2. Прикрепить файл**
1. Открой `draft`-отчёт из B1 → секция «Прикрепить файл» → выбери JPG или PDF.
2. Дождись «Загружено».

Ожидание: файл виден в списке прикреплённых. Размер и имя отображаются.
В `/root/zmed_pwa/data/reports/YYYY/MM/<id>_<hash>.<ext>` — файл реально лежит.

Результат: ⬜

**B3. Отправить (submit)**
1. Открой отчёт из B2 → «Отправить».

Ожидание: статус стал `submitted`, время submit зафиксировано. Если
`OTP_REQUIRED_FOR_SUBMIT=1` — сначала просит код с email (в MVP выключено,
просто подтверждает).

Результат: ⬜

**B4. Скачать PDF одного отчёта**
1. Открой `submitted`-отчёт → «📄 PDF».

Ожидание: скачивается PDF на русском, содержит шапку с клиникой, все поля
отчёта и миниатюры прикреплённых изображений. Шрифт читается (без «квадратов»).

Результат: ⬜

**B5. Скопировать отчёт**
1. Открой любой отчёт → «Скопировать».

Ожидание: создан новый `draft` с теми же полями, кроме даты (= сегодня).
Файлы НЕ копируются (это ожидаемо — к новой операции они не относятся).

Результат: ⬜

**B6. Удалить отчёт (только ZMed)**
1. Клиника-A — попытаться удалить свой draft через UI.
2. ZMed — удалить submitted-отчёт.

Ожидание: клиника удаляет только свои драфты. ZMed удаляет любой; в аудите
появляется запись `delete_submitted`.

Результат: ⬜

## C. Учёт на ОХ — оборот товара

**C1. Создать две локации**
1. Клиника-A → «📦 Учёт ОХ» → «Локации» → «+ Новая».
2. Создай:
   - `Склад` (kind=warehouse)
   - `Оперблок` (kind=surgery)

Ожидание: обе видны в списке.

Результат: ⬜

**C2. Приход от ZMed**
1. Вкладка «Партии» → «Приход» → заполни: артикул (например,
   `IMP-001-100`), номенклатура, lot, срок годности, штрихкод, количество
   `10`, локация-приёмник — `Склад`.
2. Сохранить.

Ожидание: партия появилась в списке; на локации `Склад` баланс = 10; в
журнале движений — строка `receive +10 → Склад`.

Результат: ⬜

**C3. Перемещение Склад → Оперблок**
1. Открой партию из C2 → «Переместить» → из `Склад` в `Оперблок`, кол-во 3.

Ожидание: баланс `Склад` = 7, `Оперблок` = 3. В журнале — `transfer 3,
Склад → Оперблок`.

Результат: ⬜

**C4. Расход на операцию**
1. «Расход» → партия из C2, с `Оперблок`, кол-во 2, при желании привязка к
   отчёту B3 (operation_report_id).

Ожидание: `Оперблок` = 1. В журнале — `consume 2 с Оперблока`, видна ссылка
на отчёт (если указана).

Результат: ⬜

**C5. Возврат**
1. «Возврат» → из `Оперблок` на `Склад`, 1 шт.

Ожидание: `Склад` = 8, `Оперблок` = 0. Строка `return 1`.

Результат: ⬜

**C6. Инвентаризация с расхождением**
1. «Инвентаризация» → партия, локация `Склад`, факт = 6 (вместо расчётных 8).

Ожидание: баланс `Склад` = 6. В журнале — `inventory_adjust -2`. На странице
«Потери» эта строка видна.

Результат: ⬜

**C7. Списание**
1. «Списание» → партия, локация `Склад`, 1 шт, причина = «просрочка».

Ожидание: `Склад` = 5. Строка `write_off -1`. На странице «Потери» видна.

Результат: ⬜

**C8. Экспорт движений в XLSX**
1. «Движения» → «📊 XLSX».

Ожидание: Excel-файл, в нём все движения с C2 по C7, колонки читаются,
даты не превратились в числа.

Результат: ⬜

**C9. Экспорт потерь**
1. «Потери» → «📊 XLSX».

Ожидание: в файле — только `write_off` + `inventory_adjust` (строки C6 и C7).

Результат: ⬜

## D. Сканирование штрихкода

**D1. USB/BT-сканер**
1. Открой «📷 Сканер» (`/clinic-stock/scan`).
2. Фокус в поле ввода (должен быть автоматически).
3. Отсканируй EAN-13 партии из C2.

Ожидание: сканер отправляет Enter, страница сама ищет и показывает партию +
баланс по локациям.

Результат: ⬜ (если сканер есть) / ➖ (пропустить, если нет)

**D2. Камера телефона**
1. На телефоне открой PWA (через HTTPS, иначе браузер откажет в камере).
2. «📷 Сканер» → «Включить камеру».
3. Разреши доступ к камере → наведи на EAN-13 партии.

Ожидание: декодер находит код, камера останавливается, показывается
результат партии.

Результат: ⬜

**D3. Ненайденный штрихкод**
1. На странице сканера введи вручную `0000000000000`.

Ожидание: «Партия со штрихкодом ... не найдена», без 500-й ошибки.

Результат: ⬜

## E. Поиск, теги, аналитика

**E1. FTS-поиск**
1. В отчёте B1 в поле «Диагноз» использовался уникальный термин, напр.
   `тестовый_термин`.
2. «📋 Отчёты клиник» → поле поиска → введи `тестовый_термин`.

Ожидание: отчёт находится. По части слова (`тестовый`) — тоже находит.

Результат: ⬜

**E2. Теги**
1. ZMed → админка `:5102` → «Теги» → создай тег «Требует разбора».
2. ZMed → «📋 Отчёты клиник» → открой любой → проставь этот тег.
3. На главной (`/home`) должна появиться плашка «Доска разбора: 1 отчёт».

Ожидание: плашка кликабельна, ведёт на `/clinic-reports?tag=...`, список
отфильтрован.

Результат: ⬜

**E3. Bulk-tag**
1. На странице отчётов — выдели 2-3 отчёта чек-боксами → «Поставить тег».

Ожидание: тег применяется ко всем выделенным.

Результат: ⬜

**E4. Аналитика врачей**
1. «📋 Отчёты клиник» → «📊 Аналитика» → выбрать период, клинику.

Ожидание: топ-врачей по числу операций, разбивка по типам, без ошибок.

Результат: ⬜

**E5. Экспорт всех PDF в ZIP**
1. ZMed → «📋 Отчёты клиник» → фильтр по периоду → «📦 PDF ZIP».

Ожидание: ZIP-архив, внутри PDF каждого отчёта за период.

Результат: ⬜

**E6. Экспорт отчётов в XLSX**
1. ZMed → «📋 Отчёты клиник» → «📊 XLSX».

Ожидание: таблица со всеми полями отчётов за выбранный период.

Результат: ⬜

## F. Уведомления

**F1. Email о новом submitted-отчёте**
1. На проде в `.env` должен быть `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`.
2. В админке `:5102` → «Рассылка» → должен быть хотя бы один адресат с
   kind=`reports` или `all`.
3. Клиника отправляет отчёт (как в B3).

Ожидание: на email адресатов приходит письмо с темой «Новый отчёт об
операции» и ссылкой.

Результат: ⬜

**F2. Напоминание о молчащих клиниках**
1. Создай клинику-пилот, но НЕ подавай от неё ни одного отчёта.
2. Подожди пн-пт 10:00 МСК (или вручную дёрни `clinic_silence_check`).

Ожидание: на адресатов рассылки приходит сводное письмо «Молчат N клиник»
со списком. У клинических юзеров с tg_id — персональное TG-напоминание.

Результат: ⬜ (проверяем на пилоте в течение 2 недель)
